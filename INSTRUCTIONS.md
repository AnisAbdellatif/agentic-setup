# Claude Code environment setup — instructions for an LLM

You are Claude Code (or another agent) on a fresh machine. Rebuild the user's Claude Code environment from this repo. This file is the source of truth; adapt steps to the OS and to what is already installed. If the user says "dry run", only report what you would do.

## Rules
- Idempotent: inspect current state first; skip anything already done.
- Never overwrite without a backup: move `~/.claude/<item>` to `<item>.bak.<YYYYMMDD-HHMMSS>` first.
- Never write secrets into this repo. Secrets come from env vars or interactive login.
- Ask before: installing system packages, running remote install scripts (`curl | sh`), or touching anything outside this repo and `~/.claude`.
- Support macOS and Linux. Report failures plainly and continue with independent steps.
- Finish with a checklist: linked / installed / skipped / manual steps.

## Getting this repo
You may be reading this file from its raw URL (`https://raw.githubusercontent.com/AnisAbdellatif/agentic-setup/main/INSTRUCTIONS.md`) with no local checkout. The steps below need a persistent checkout (`~/.claude/*` are symlinks into it), so first: if the current directory is not a checkout of this repo and `~/dev/agentic-setup` does not exist, run `git clone https://github.com/AnisAbdellatif/agentic-setup.git ~/dev/agentic-setup` (use `git@github.com:AnisAbdellatif/agentic-setup.git` instead if the user wants to push) and treat it as "this directory" below. Never ask the user to clone it by hand.

## 0. Choose what to install (ask first)
Before touching anything, ask the user: **everything, a preset, or pick components**. Use AskUserQuestion if available, else a numbered list. Honor "dry run": print the plan for the chosen set, change nothing.
- Presets: `full` (all below), `minimal` (core only), `server` (headless Linux box: core, tokenade, goldfish, ponytail, humanizer, model-chooser, find-skills; skips desktop/Mac-only parts), `custom` (user ticks components).
- Components (id: what; needs): `core` (CLAUDE.md, agents, settings; always), `tokenade` (CLI, hooks, statusline; node), `plugin:goldfish` (bun), `plugin:ponytail` (node), `plugin:humanizer`, `plugin:academic-research-skills`, `plugin:agent-estimate` (uv), `skills-cli` (find-skills, security-audit, frontend-design, web-design-guidelines, check-originality, humanize-academic-writing; node), `own-skills` (typst, d2, model-chooser; typst/d2 need brew or cargo), `graphify` (uv), `rea` (node, Mac mostly), `t3-omniroute-sync` + section 5b `t3-config` (T3 Code desktop only), `proton-ssh` (`CLAUDE.proton-ssh.md`: Proton Pass SSH agent rules; ask "does this device use the Proton Pass SSH agent?", independent of OS), `extras` (firmware, Rust cache).
- Record the answer: write `~/.claude/setup-selection.json` as `{"skip": ["<id>", ...]}` listing every component NOT chosen (e.g. `"tokenade"`, `"plugin:ponytail"`). `scripts/settings.py` reads it and drops the matching hooks/statusline/plugins/marketplaces from the compiled `settings.json`. Re-run the interview any time to change it, then `python3 scripts/settings.py`.
- Skip every later step whose component is not selected, and prerequisites only needed by skipped components. Add a skipped item to `skip` rather than deleting it from the repo.

## 1. Prerequisites
Check: `claude`, `git`, `jq`, `node`+`npm`, `uv`, `bun`, `gitleaks` (pre-commit secret scan; `brew install gitleaks` or the release binary). Report missing ones with the install hint; install via the system package manager only after asking.
- Bare machine (no `claude`/`node`): ask, then install Node >=20 (system pkg manager, `fnm`, or NodeSource on Debian) and `npm i -g @anthropic-ai/claude-code`, put the global npm bin on the non-interactive PATH (`~/.profile`, not only `.zshrc`), clone this repo, and continue. Hooks call bare `tokenade`, so it must resolve there too.
- `bun` is needed by the goldfish plugin's MCP server (https://bun.sh).
- Git default branch: run `git config --global init.defaultBranch main` (new repos use `main`, not `master`).

## 2. Link owned config into `~/.claude`
Repo path = this directory. Run `sh scripts/install.sh` (idempotent; every line starts with `ok`, `link`/`add` = wrote something, `skip`, or `SKIP` = fix by hand; a second run prints no `link`/`add`). It links `CLAUDE.md`, `agents`, `commands`, `hooks` into `~/.claude` (backing up an existing item to `<item>.bak.<ts>`), makes `CLAUDE.md` read-only, links `~/.codex/AGENTS.md` to `CLAUDE.md` when `~/.codex` exists (one rules file for Codex too), sets `core.hooksPath .githooks` (gitleaks pre-commit), creates `~/.claude/settings.private.json` (600) from the example if missing, and builds settings. One phase only: `--links-only`, `--githooks-only`, `--settings-only`. The bullets below explain what it does and what it leaves to you.
- Then `chmod 444 CLAUDE.md` (git doesn't keep it). tokenade's SessionStart `cascade_dedup` treats `~/.claude/CLAUDE.md`, `~/claude_omniroute/CLAUDE.md` and this repo's `CLAUDE.md` as separate files and strips "duplicates" from what is really one file, leaving only headings. Read-only blocks that; `chmod u+w CLAUDE.md` to edit, then `chmod 444` again. If it already happened: `git checkout -- CLAUDE.md`.
- Machine-local instructions: `CLAUDE.md` ends with `@~/.claude/CLAUDE.local.md` (a missing file is ignored). If `proton-ssh` is chosen: `ln -sfn <repo>/CLAUDE.proton-ssh.md ~/.claude/CLAUDE.local.md`. Other devices leave it absent or write their own notes there. Never put device-specific rules in `CLAUDE.md`.
- Settings are compiled, not linked: `~/.claude/settings.json` = `settings.common.json` (repo, shared) + `~/.claude/settings.private.json` (machine-specific/secret: `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_KEY`, never in git). If `~/.claude/settings.private.json` is missing, create it (`600`) from `settings.private.example.json` and ask the user for the key; move any private values out of an existing `~/.claude/settings.json` into it (back the old file up first). Then run `python3 scripts/settings.py build`.
- `python3 scripts/settings.py` (= `sync`) folds edits Claude/tools made to `~/.claude/settings.json` (plugin installs, `/config`, tokenade hooks) back into `settings.common.json` / the private file (keys already private stay private; new env vars named `*KEY*`, `*TOKEN*`, `*SECRET*`, `*PASSWORD*`, `*BASE_URL*` go private), then rebuilds. A `SessionStart` hook in `settings.common.json` runs it (plus `t3-omniroute-sync --link-only` if installed) at every session start; run it by hand to apply a change immediately. Commit `settings.common.json` afterwards. Edit the source files, not the compiled one.
- Safety layers in `settings.common.json`:
  - `permissions.deny`: `Read` of `.env*`, keys, `~/.ssh` and similar for Claude's file tools.
  - `hooks/guard.py` (PreToolUse Bash): blocks force push (`--force-with-lease` is allowed), `--no-verify`, recursive `rm` of `/` or home, reading secret/key files (`.env*`, `*.pem`, `~/.ssh`, `~/.aws`, …) with cat/grep/head/etc., and echoing secret env vars. Text filter, not a sandbox: there is no Bash sandbox on purpose (T3 Code Full access cannot disable it). Self-check: `python3 hooks/test_guard.py`.
  - `hooks/format.py` (PostToolUse Edit/Write): formats the edited file with the project's formatter (biome/prettier from `node_modules`, `ruff` when configured, `gofmt`, `rustfmt`). Repo-local `node_modules` tools only run for repos under a trusted root: `~/.config/claude-hooks/trusted-roots`, one path per line, default `~/dev`.
- `~/.claude/skills` is a real directory in practice (tool-installed skills live there); the repo `skills/` stays empty. `graphify`, `reverse-engineer-anything`, `find-skills`, `security-audit`, `frontend-design`, `web-design-guidelines`, `check-originality`, `humanize-academic-writing`, `typst`, `d2`, `model-chooser`, and `synced` are tool-installed, not owned.

## 3. Marketplaces and plugins
Read them from `settings.common.json` (`extraKnownMarketplaces`, `enabledPlugins`) rather than from this text, so this stays in sync:
1. For each marketplace not shown by `claude plugin marketplace list`: `claude plugin marketplace add <repo-or-url>` (github source → `owner/repo`; git source → URL).
2. For each plugin set `true` in `enabledPlugins` and not in `claude plugin list`: `claude plugin install <name>@<marketplace> --scope user`.
3. Always target `~/.claude`: run with `CLAUDE_CONFIG_DIR=~/.claude` (or unset). Inside a T3 OmniRoute session it points at `~/claude_omniroute`, and installs would land in that folder's settings instead of this repo's. Afterwards run `python3 scripts/settings.py` (pulls it into `settings.common.json`) and `t3-omniroute-sync --link-only` (section 4) so the OmniRoute folder's settings pick up the plugin.
- Current plugins: `academic-research-skills` (research/writing/review pipeline, CC-BY-NC-4.0), `goldfish` (needs `bun`), `humanizer` (blader/humanizer — install as plugin only, not also via `npx skills`, or the skill copy is shadowed), `ponytail` (DietrichGebert/ponytail; its hooks need `node` on the non-interactive PATH; 4 optional userConfig options via `/plugin configure ponytail@ponytail`), `agent-estimate` (kiloloop/agent-estimate, marketplace `agent-estimate-marketplace`; PERT time/cost estimates for agent tasks; also needs the CLI: `uv tool install agent-estimate`, check `agent-estimate --version`).

## 5. MCP servers (user scope)
None besides `rea` (section 4) and goldfish's (from its plugin). To add one:
`claude mcp add --scope user <name> ...`, secrets from env vars (e.g. `--header "Authorization: Bearer ${X_API_KEY}"`); skip with a note if the var is unset. Check `claude mcp list` first. Record new servers here.

## 5b. T3 Code config (`t3/`)
Symlink only the portable files, with T3 quit: `for f in settings.json client-settings.json keybindings.json; do ln -sf "$PWD/t3/$f" ~/.t3/userdata/$f; done` (back up any existing file first). Never sync `statev2.sqlite*`, `secrets/`, `clerk/`, `providers/`, `environment-id`, `anonymous-id`, `server-*`, `connection-catalog.json`, `desktop-*`, logs or caches. Non-secret Claude provider env vars (`ANTHROPIC_BASE_URL`, `CLAUDE_CODE_SUBAGENT_MODEL`, `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY`, `ANTHROPIC_DEFAULT_HAIKU_MODEL`, all `sensitive: false`), custom models (`ag/*` slugs in `providerInstances.claudeAgent.config.customModels`) and `modelOrder` are stored in `t3/settings.json`. Only `ANTHROPIC_API_KEY` (`sensitive: true`) is redacted by T3 — re-enter it in T3 (Claude provider instance → environment) on each device. If T3 replaces a symlink with a regular file on save, copy it back into `t3/`.
- Prefer running `t3-omniroute-sync` (`https://github.com/AnisAbdellatif/t3-omniroute-sync`, see section 4) to set up or refresh the OmniRoute provider instance in T3 Code, pull the live model catalog, configure `~/claude_omniroute/settings.json`, and link `~/claude_omniroute/` to `~/.claude`. Set everything up in `~/.claude` only; re-run `t3-omniroute-sync --link-only` after changing `~/.claude/settings.json`.
- Optional daemon (keeps OmniRoute models fresh + shows OmniRoute quota in T3 Usage → Limits): 1) run the wizard (creates `~/.config/t3-omniroute-sync/daemon.json`), then put a manage-scope OmniRoute key in its `server.quotaKey` (the user can do this and edit the model rules in the TUI `t3-omniroute-sync config`, with live preview, test and save+sync) (a chat-only key syncs models but gets 401/403 on quota; ask the user for it, never copy it from `settings.private.json`); check with `t3-omniroute-sync daemon --once --dry-run`; 2) `t3-omniroute-sync install-service --start` (launchd agent on macOS, systemd user unit on Linux, Task Scheduler on Windows; writes and (re)starts it); log in `~/Library/Logs/t3-omniroute-sync.log`; config edits apply within seconds, no restart; verify with `t3-omniroute-sync doctor` (all ✓); 3) tell the user to add the HTTP source once in T3: Settings → Providers → Usage providers → Add HTTP source, URL `http://127.0.0.1:20130/quota`, token from `~/.config/t3-omniroute-sync/quota-token`. `t3/settings.json` goes through the `t3models` git clean filter (`.gitattributes`), which stores the generated Omniroute `customModels` as `[]`, so daemon model updates make no diffs. t3-omniroute-sync (0.6+) defines the filter in the global git config on every run (wizard, `--link-only` from the SessionStart hook, daemon), so no per-machine step; check with `git config --global --get filter.t3models.clean`. Until it has run once on a machine, git silently commits the full list.

## 6. Manual steps to tell the user
- Put the OmniRoute key in `~/.claude/settings.private.json` (`env.ANTHROPIC_AUTH_KEY`), export `ANTHROPIC_AUTH_TOKEN` in the shell profile, or log in via `claude` — never in `settings.common.json`. If an old local `settings.json` holds it, move it to the profile before linking.
- `settings.private.example.json` sets `ANTHROPIC_BASE_URL` to `http://<omniroute-host>:20128` (Tailscale): join the tailnet or edit it in the private file.
- `claude-opus-4-8` is used in `CLAUDE_CODE_SUBAGENT_MODEL`; confirm the ID is valid.
- Restart Claude Code; accept trust prompts for marketplaces/plugins.

## 7. Verify
`sh scripts/doctor.sh` (read-only; `ok`/`MISSING <what>: <fix>`/`WARN`, exits 1 if anything is missing), `tokenade health`. Then print the checklist.

## Firmware analysis tools
`brew install squashfs sevenzip` (unsquashfs for Buildroot rootfs, 7zz for ext2/ext4). Extract squashfs onto a case-sensitive APFS image (`hdiutil create -fs "Case-sensitive APFS"`), since macOS's default FS drops case-colliding files.

## Rust build cache
`~/.cargo/config.toml`: `[build] target-dir = "$HOME/.cache/cargo-target"` (write the absolute path) so every project and git worktree shares one `target`. Concurrent cargo builds serialize on its lock. Prune with `cargo install cargo-sweep && cargo sweep --time 14 ~/.cache/cargo-target`.

## Maintaining this file
When the user adds a plugin, tool, MCP server, or secret requirement, update the matching section here. Add plugins/marketplaces to `settings.common.json` (or install them and run `scripts/settings.py`), not just here. `scripts/settings.py` normalizes tokenade absolute paths to `$HOME` / bare `tokenade` when folding edits into `settings.common.json`; still check `git diff settings.common.json` and never commit tokens or `setup-selection.json` (machine-local).
